## 深度隐藏分析

### 检测到了什么（穿透隐藏层的信号）

1. **C5 包指纹 → APatch（B 级）**：包枚举 + DEX 内容扫描穿透了隐藏层
2. **C11 无障碍服务 → 3 个未知服务（C 级）**：作弊框架的无障碍组件被枚举到
3. **C12 ADB → 远程控制指示（C 级）**：ADB 启用被检出

### 被什么隐藏挡住了

| 隐藏手段 | 挡住的检测 | 影响 |
|---|---|---|
| **susfs 挂载命名空间** | /system/bin/su、/data/adb/、overlay 挂载 | C1/C2 全盲 |
| **resetprop 属性清除** | init.svc.magisk*、test-keys、属性区空洞 | C3 全盲 |
| **APatch supercall 需 superkey** | 内核探针无法获得 HELLO 响应 | C8 supercall 失效 |
| **不注入目标进程** | prologue/GOT/maps 完整性检查全通过 | C6/C7 无异常 |
| **SELinux hide** | magisk/ksu 域标签不存在 | C8 SELinux 失效 |

### 关键发现：为什么只有 32 分

我们的评分模型要求 **两条 B 级（跨域）** 才定性。当前只有 1 条 B（APatch）：
- AUTOMATION 的 3 条都是 **C 级**（未知无障碍服务，白名单外）
- REMOTE_CONTROL 是 **C 级**（仅 ADB，未满足三条件组合）

**如果有 Lucky Patcher 条目（B 级）**：APatch(B) + Lucky Patcher(B) = 双 B 共振 → **50+ 定性**
